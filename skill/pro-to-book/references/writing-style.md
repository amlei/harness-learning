# 写作、引用与配图细则

SKILL.md 的规则在这里展开成可照做的模板与清单。

## 篇文件模板

```markdown
# 第N篇　标题

*作者：Amlei　·　更新时间：YYYY-MM-DD*

> 一段引子：本篇剖析什么、为什么重要。第三人称。

---

## 第 1 章　章标题

### 1.1　节标题

正文段落……。涉及它篇时就地用链接：（见[第三篇](part-03-tools.md)·第 6 章）。

```python
# 代码块：标注文件:行号
# run_agent.py:1415
while api_call_count < max_iterations: ...
```

\`\`\`mermaid
flowchart TD
  A --> B
\`\`\`

> 知识补充（可选）：对生僻概念的就地解释；或回指"概念见第〇篇·X"。

---

## 第 N 章　为何如此设计：权衡的总账

1. 权衡一……
2. 权衡二……

---

*第N篇完。下一篇……*
```

**要点**
- 首行 `# 第N篇　标题`（用全角空格「　」分隔篇号与标题）。**篇号用"第 N 篇"，不是"部"**。
- 次行署名 + 更新时间（日期级，`YYYY-MM-DD`）。
- `文件:行号` 以注释或行内 `(\`file.py:123\`)` 标注，便于代码导航。
- 每篇结尾有"权衡总账"。

## 篇号 → 文件名映射（约定）

`第N篇` ↔ `part-NN-<slug>.md`，交叉引用按此解析：
- 第〇篇=part-00-preface、第一篇=part-01-overview、第二篇=part-02-core-loop …… 第十四篇=part-14-feature-tools ……
- 转换链接时：`第N篇·第X章 标题` → `[第N篇·第X章 标题](part-NN-<slug>.md)`，slug 取自目标篇文件名；必须具体到章/节标题。

## 交叉引用（就地链接，具体到标题）

核心规则与"不转换"清单见 SKILL.md「交叉引用」，此处只补可操作示例与边界：

```
[第三篇·第 6 章 工具集体系](part-03-tools.md)
（见[第二篇·第 5 章 缓存稳定性纪律](part-02-core-loop.md)）
```

- 按上一节「篇号 → 文件名映射」把篇号解析成目标文件名。
- 列举式（"第二、三篇"）可只链末项或保持纯文本；不强求每个都链。
- 阅读器把 `a[href$=".md"]` 拦截改写为同卷 hash 路由，点击即跳转；在 GitHub 上仍是相对链接，也工作。

## 配图

- **Mermaid**（复杂）：`flowchart`/`sequenceDiagram`/`stateDiagram`/`erDiagram`/`classDiagram`。用于架构、控制流、状态机、时序、数据模型、依赖图。
- **ASCII**（简单）：依赖链、数据流、命令速查、目录树。用纯字符，等宽对齐。
- 原则：**只在"配图才好讲"处用**；每篇 1–3 张；图必有简短图注。
- Mermaid 配色由 `reader.js` 读主题 CSS 变量自动适配（浅底→`default`、深底→`dark`），勿在图源里写死颜色。

## 反"知识诅咒"（受众是未知深度的学习者）

- **part-00「概念入门」**：把全书反复出现的生僻术语各写一条学习者级解释（2–5 句，第三人称，标注"主要出现于第几篇"）。覆盖范围如：AI Agent 循环、function calling、token/上下文窗口、**提示缓存/prefix cache**、OpenAI 兼容 API、transport 适配、同步循环+异步桥接、进程/线程/GIL、子进程/守护/孤儿、SQLite/FTS5/WAL、SSRF/OS 安全边界、插件/ABC/注册表、MCP、CDP/无障碍树、MoA、Profile、辅助模型、reasoning token……（**领域专有名词保留源词**：Agent 即"智能体"，不译作"代理"；token、prefix cache、transport、MCP、CDP、FTS5、WAL、asyncio、ABC、GIL、MoA 等同理保留英文，必要时以括注释义。）
- **正文**用到这些术语时，必要时回指"（概念见第〇篇·X）"。
- **就地"知识补充"**：某段需要展开的背景，在段后加一小段解释（引用块或普通段）。
- 默认读者**不一定**懂 FTS5/WAL/CDP/SSRF/asyncio/ABC…… 该解释就解释。

## 第三人称客观

- 通篇第三人称（"本篇剖析……""系统采用……"），不用"你""我们"。
- 不评判好坏，只呈现"如何工作、为何如此设计、代价是什么"。

## 详略

- **深挖**：核心机制到 `文件:行号`、到控制流/数据流/算法。
- **点到即止**：边缘/产品化内容（计费、relay、特定平台怪癖、合规细节）。
- 每篇末尾"权衡总账"收束 5–10 条取舍。

## 勘误

- 与上游既有文档（CLAUDE.md、README、早期注释）的**出入**要显式标注为更正，例如：
  > **一处重要校正**：CLAUDE.md 说"核心循环在 run_agent.py"，实际已模块化迁移到 `agent/conversation_loop.py`。
- 这类勘误体现精确性，是本类书的价值之一。

## 全文概览（part-00）必含

1. **序言**：受众、立场、反知识诅咒、组织方式。
2. **读者指南**：如何读、导航锚点、详略体例。
3. **概念入门**：上述释疑层。
4. **总目录**：每篇主旨 + 前置/延伸。
5. **章节关系图**：Mermaid 依赖图。
6. **贯穿主线**：全书几条设计 DNA。
